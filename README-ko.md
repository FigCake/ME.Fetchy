# Fetchy

[Marinara Engine](https://github.com/Pasta-Devs/Marinara-Engine)용 확장 설치기. zip을 내려받아 손으로 가져오는 대신 GitHub URL로 외부 확장을 설치하고 업데이트합니다. English: [README.md](README.md)

## 기능

* **URL로 설치** — GitHub 저장소(`owner/repo`, `/tree/<브랜치>/<폴더>` URL, `owner/repo/<폴더>@<브랜치>`), raw `manifest.json` URL, `.zip` URL. 브랜치를 안 적으면 `main`, 없으면 `master`
* **보내기 전 미리보기** — 이름·버전·설명·런타임·권한(`full_page_access`는 붉은 경고), 파일 크기, README, 내려받은 코드 전문, 그리고 Marinara가 Review and Run에 표시할 콘텐츠 해시
* **변경 사항** — Marinara에 이미 있는 확장이면 현재 버전·상태, 파일별 크기 전후, 추가·삭제된 줄 수, Marinara 편집기에서 손으로 고친 코드가 있으면 경고
* **설치·업데이트·연결** — Marinara의 자체 API로 레코드를 만들거나 기존 레코드를 업데이트하고, 손으로 설치한 확장은 코드를 바꾸지 않고 연결만 합니다. 모든 설치는 사용자가 해시를 승인할 때까지 비활성
* **FigCake 확장** — 패널 위쪽 **🍰 묶음 설치**로 열어서 Dispensa·Fornello·Polyglot을 골라 GitHub 저장소에서 한 번에 차례로 설치. 하나씩 설치할 때처럼 꺼진 상태로 들어가고(이미 있으면 업데이트, 코드가 같으면 연결만), 켜는 것은 Marinara에서 하나씩 승인(“업데이트한 확장 켜 두기”를 켜 두면 켜져 있던 것의 업데이트는 바로 다시 켜짐). 이 중에 업데이트가 있으면 케이크에 색이 들어옴
* **확장 관리** — Marinara의 외부 확장을 한 목록에서: 켜짐·꺼짐·승인 필요 표시, 권한 배지, 코드 보기, 끄기와 다시 켜기, 삭제, 리비전 되돌리기. Fetchy로 설치한 것은 업데이트 확인(하나씩 또는 모두)과 업데이트, 손으로 설치한 것은 GitHub 주소 연결. 내 폴더와 태그(옵션 → 폴더와 태그에서 만들고, 각 확장의 더보기에서 지정), 목록 위 태그 거르기. 패널을 열 때 모든 확장의 업데이트를 확인, 30분 안에 확인한 것은 건너뜀(끌 수 있음. **모두 확인**은 전부 확인. 공개된 GitHub 파일만 읽어서 비용이 들지 않음)
* **모두 업데이트** — 확인에서 찾은 업데이트를 한 번에 적용. “업데이트한 확장 켜 두기”를 켜 두면(확인 한 번 필요) 개별이든 전체든 여기서 하는 업데이트는 켜져 있던 확장을 새 코드로 승인해 바로 다시 켭니다. 새 권한을 요구하는 버전은 제외
* **자동 업데이트(확장마다, 기본은 꺼짐)** — 확장의 더보기에서 켜면 Fetchy가 업데이트를 알아서 설치: 마리나라를 열 때(최대 6시간에 한 번)와 패널을 열 때 확인한 뒤. 새 코드는 마리나라가 승인할 때까지 꺼져 있고, 자동 승인이나 “업데이트한 확장 켜 두기”가 켜져 있으면 다시 켜짐. Fetchy 설치 뒤 Marinara에서 코드를 바꾼 확장은 건너뛰고 알려 줌(바꾸려면 따로 업데이트). Fetchy 자신에는 없음
* **리비전** — Marinara가 보관한 이전 리비전으로 되돌리기. 되돌린 코드도 다시 승인 필요
* **내보내기 / 가져오기** — 소스 목록을 JSON으로. 다른 브라우저나 다른 Marinara로 옮길 때. 가져오기는 목록에 없는 확장만 자동 업데이트·자동 승인을 끈 채 더함. 이미 있는 확장은 주소와 설정 유지
* **할 일을 알려 주는 오류** — 외부 확장 게이트 두 개, Admin Access, 허용되지 않은 호스트, CSRF, CORS, GitHub API 한도, 다운로드 중 바뀐 소스
* **변경 기록** — 설치·업데이트·연결·되돌리기·제거를 버전·해시·권한과 함께 기록. 패널이 닫힌 사이 끝난 업데이트는 다음에 열 때 기록에 반영
* **업데이트 후 자동 승인 (확장별, 기본 꺼짐)** — 켜 두면 업데이트 뒤 Fetchy가 새 코드를 승인해 다시 켭니다. 켤 때 Marinara 승인 창과 같은 확인 두 가지에 직접 체크해야 하고, 업데이트 전에 켜져 있던 확장에만, 그리고 새 권한을 요구하지 않는 버전에만 적용됩니다. **이 옵션을 켠 확장은 저장소 주인이 올린 코드가 내 검토 없이 실행됩니다.** 믿는 제작자에게만 쓰세요
* **권한 경고** — 업데이트가 새 권한을 요구하거나, 버전은 그대로인데 코드만 바뀌었으면 크게 알림
* **다시 켜기** — 더보기에서, 꺼진 확장을 전에 승인한 코드 그대로일 때만(같은 해시) 다시 켭니다. full page access 확장은 Marinara 승인 창과 같은 확인을 먼저 받습니다. 코드가 바뀌었으면 Marinara에서 다시 승인해야 함
* **업데이트 알림** — Marinara를 열고 조금 뒤(최대 6시간에 한 번) 출처마다 `manifest.json`만 읽어 새 버전이 있으면 작은 알림을 띄웁니다. 같은 버전은 한 번만. 업데이트가 있으면 설정의 Fetchy 단추에 점, Fetchy 새 판은 패널 위쪽에 「출처로 추가해 업데이트」와 함께 표시. 끌 수 있음
* **바뀐 내역** — 업데이트가 있는 확장은 설치한 커밋 이후 그 폴더에서 바뀐 커밋을 최근 것부터 20개 보여 줌(펼칠 때만 읽음)
* **저장소 표시** — 설치된 확장 이름 옆에 「보관됨」, 「6개월 이상 갱신 없음」(저장소마다 일주일에 한 번 GitHub에 물음)
* **선택** — 여러 줄을 체크해 숨기기(맨 아래 모음에서도 업데이트는 알려 줌), 태그 붙이기, 충돌 분석
* **충돌 분석** — full page access 확장의 코드를 실행하지 않고 글로만 읽어 페이지에서 차지하는 이름(전역, 커스텀 요소, 요소 id, 저장 키, Dispensa 명령, 단축키, `!important` 스타일)을 찾습니다. 설치 미리보기에서는 설치된 확장과, 선택 모드에서는 고른 확장끼리 비교. 충돌은 빨강, 참고는 회색, 근거 줄과 함께. 설치는 막지 않음
* **저장 공간** — 확장마다 저장 데이터 크기를 Marinara 한도(1 MB) 대비로, 큰 키와 함께. 파일로 백업, 복원(지금 데이터를 먼저 파일로 저장), 비우기(백업 파일을 받고 이름을 다시 입력한 뒤). 브라우저 쪽 저장 공간은 보기만
* **켜짐 묶음** — 지금 켜진 확장을 이름 붙여 저장하고 나중에 그 묶음으로 바꾸기
* **문제 확장 찾기** — 반을 끄고 새로고침 뒤 문제가 남았는지 물어 반씩 줄여 하나를 찾음. 새로고침을 넘어 이어지고, 그동안 자동 업데이트는 쉼. 언제든 원래대로 되돌리기
* **전체 백업** — 출처 목록, 폴더와 태그, 고른 확장의 저장 데이터를 파일 하나로. 다른 브라우저나 Marinara로 옮길 때
* **진단 복사** — 버그 신고에 붙일 글: Marinara·Fetchy 버전, 관문 상태, 브라우저, 확장마다 상태·출처·마지막 확인, 마지막 충돌 분석, 변경 기록. 코드·저장 데이터·관리자 비밀은 넣지 않음
* **처음 설정 도우미** — Fetchy로 설치한 것이 없을 때 패널을 처음 열면: Marinara가 허락하는 것, FigCake 확장 고르기, 옵션, 설치, 승인 안내
* **다른 추천 목록** — 묶음 설치 창에서 다른 사람의 목록을 주소로 추가. 설치는 지금처럼 하나씩 미리보기를 거침
* **한국어·영어 UI**, 라이트·다크 테마, 좁은 화면에서는 바텀 시트

## 설치

1. 서버 `.env`에 `ENABLE_EXTERNAL_EXTENSIONS=true` 를 넣고 Marinara 재시작
2. 설정 → 애드온(Addons) → 외부 확장(External Extensions): **Allow third-party extension imports** 를 켜고 `ME-Fetchy-<버전>.zip` 가져오기
3. 목록의 **Fetchy** → **Review and Run**: 코드를 읽고 해시 승인 (`SHA256SUMS.txt`의 값과 같아야 함)
4. 같은 화면(설정 → 애드온 → 외부 확장)의 가져오기 버튼 옆에 **GitHub에서 설치 (Fetchy)** 버튼이 나타남. 단축키 Alt+Shift+F. 설명은 작은 (?) 표시에 마우스를 올리면 나옴

원격(localhost가 아닌) Marinara는 서버 `.env`의 `ADMIN_SECRET`을 설정 → Admin Access에 입력해야 합니다. Fetchy 자신을 업데이트하려면 소스에 `FigCake/ME.Fetchy`를 추가하세요(새 판이 나오면 패널이 추가를 권합니다).

## 안전한가요

Fetchy는 설치 도우미일 뿐입니다. 코드를 내려받아 Marinara에 **꺼진 상태로** 넣어 두기만 하고, 직접 실행하지는 않습니다. 켜는 것은 사용자입니다(확장별로 자동 승인을 켠 경우만 예외): 설정 → 애드온 → 외부 확장에서 코드를 보고 **Review and Run**으로 승인해야 돌아갑니다. Fetchy가 미리 보여 주는 해시와 그 화면의 해시가 같으면 받은 그대로입니다.

업데이트도 같습니다. 새 코드가 들어가면 확장은 다시 꺼지고, 승인해야 다시 켜집니다. 그래서 모르는 사이에 바뀐 코드가 돌아가는 일은 없습니다.

확장을 다시 켜는 것(더보기, 켜짐 묶음, 문제 확장 찾기)은 새로 승인하는 일이 아닙니다. Marinara가 그 코드 그대로(같은 해시)에 대한 승인을 아직 갖고 있을 때만 켜고, 켜기 직전에 한 번 더 확인합니다. 바뀐 코드는 Marinara에서 직접 승인해야 합니다. Fetchy 자신은 끄지 않습니다.

충돌 분석은 코드를 글로 읽을 뿐 실행하지 않습니다. 확장의 저장 데이터는 사용자가 요청한 파일(백업)로만 나가고, 진단 정보와 변경 기록에는 저장 데이터·코드·관리자 비밀이 들어가지 않습니다.

GitHub에서 파일을 받을 때 로그인이나 토큰은 쓰지 않습니다. 공개 저장소만 됩니다. 설치·업데이트는 모든 파일을 한 커밋에서 읽으므로 내려받는 도중에 푸시가 있어도 두 버전이 섞이지 않습니다.

## 내 확장을 Fetchy로 설치되게 하려면

저장소에 이 두 파일만 있으면 됩니다.

```
manifest.json      ← Marinara 외부 확장 매니페스트 (zip 가져오기에 쓰는 것과 같음)
extension.js       ← manifest.json의 jsPath가 가리키는 파일
```

둘을 저장소 맨 위에 두면 사용자는 `owner/repo`만 입력합니다. 폴더 안에 두어도 되는데, 그러면 사용자가 `owner/repo/폴더`를 입력합니다.

* 새 버전을 올릴 때 `manifest.json`의 `version`을 올리세요. Fetchy가 그걸 보고 업데이트를 알립니다.
* `capabilities`는 비어 있어도 꼭 적으세요 (`[]`). 없으면 Marinara가 구형 확장으로 봅니다.
* GitHub Releases에 올린 zip은 브라우저가 받을 수 없습니다. zip으로 배포하려면 저장소 파일로 커밋하고 그 파일 주소를 알려 주세요.

## 요구 사항

* Marinara Engine 2.5.0 이상, 외부 확장 허용
* zip 소스를 쓰려면 `DecompressionStream`을 지원하는 브라우저 (Chrome, Edge, Firefox, Safari 16.4+)
